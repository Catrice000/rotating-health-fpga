# 串口协议

230400 baud，8N1，无硬件流控。
帧为 `C3 3C TYPE LENGTH PAYLOAD CRC_LO CRC_HI`。
CRC16-CCITT，初值 FFFF，多项式 1021，覆盖 TYPE、LENGTH、PAYLOAD；无反射，无最终 XOR。
所有整数使用小端，负数用二进制补码。

## TYPE 1，42 字节

Python struct：`<III6hiIHHBBHH`。
依次为：样本序号 u32、FPGA 毫秒 u32、I²C 错误数 u32、原始 XYZ i16×3、滤波 XYZ i16×3、
编码器计数 i32、有效边沿数 u32、非法跳变 u16、flags u16、设备 ID u8、A/B 电平 u8、
样本覆盖次数 u16、频谱覆盖次数 u16。

flags：bit0 初始化完成；bit1 数据新鲜；bit2 FFT 输入丢样；bit3 曾有编码器非法跳变；
bit4 电机运行命令；bit5 方向；bit6 基线有效；bit7 学习中；bit8～9 速度档 0/1/2。
相同样本序号的状态心跳不应再加入波形数组。

## TYPE 2，14 字节

`<IHii`：FFT 帧号 u32、bin u16、实部 i32、虚部 i32。bin 0～128。
FFT 内部 24 位有符号，发送时符号扩展到 32 位；保留 6 个小数位，Hann 窗，FFT /256。
按 bin 收齐整个帧再显示。单边幅值需补偿 Hann 增益和 /256；DC、Nyquist 不乘双边到单边的 2。

## TYPE 3，72 字节

前 4 字节为特征帧号，随后 64 字节为 FPGA 特征整数，最后为 health、fault 和两个保留字节。
64 字节特征的位偏移：

| 偏移 bit | 位宽 | 含义 |
|---:|---:|---|
| 0 / 48 / 96 | 48 各 | X/Y/Z 平方和 |
| 144 | 64 | X 四次方和 |
| 208 / 224 / 240 | 16 各 | XYZ 绝对峰值 |
| 256 | 16 | X 过零次数 |
| 272 / 304 | 32 各，有符号 | X 对编码器 1× sin/cos 的相关和 |
| 336 / 368 | 32 各，有符号 | X 对编码器 2× sin/cos 的相关和 |
| 400 | 32，有符号 | 窗口首末采样之间的编码器计数差 |
| 432～511 | 80 | 保留 |

所有特征基于连续 256 个成功采样点；相关和已除去 Q15 查表缩放。
health 是相对基线能量与速度变化的规则评分；fault=0 无当前规则触发/未标定，1 为振动能量异常，4 为转速偏离，8 为本窗数据无效。
判断健康必须同时检查 flags 的基线/数据/运行状态，不能只检查 fault=0。

## 吞吐与丢失

样本优先、特征其次、频谱最后。独立的周期状态心跳不依赖 ADXL345 成功采集。
每类有待发快照，覆盖时计数；上位机也检查序号和 CRC。
当前 200 Hz + 256 点 FFT 流量低于 230400 baud 的容量，下行电机控制协议见后面的控制扩展。


# 2026-11-04 控制扩展

新版 TYPE 1 样本为 44 字节：原 42 字节后追加 target_rpm u16。
flags bit10 为上位机启动所有权，bit11 为控制心跳超时停车记录（再次明确启动时清除）。
上位机兼容旧 42 字节遥测，但收到旧格式时禁用启动、调速和换向，提示下载新位流。

下行 TYPE 0x10，长度 5：`<BHH` = opcode u8、value u16、request_id u16。
CRC 规则与上行相同。opcode=1 停止，2 启动，3 设置 RPM（10～120），4 设置方向（0/1，必须停机），6 心跳。
上位机约每 0.4 秒发送心跳；心跳无确认帧，远程启动后约 2 秒超时停机。

上行 TYPE 0x11，长度 8：`<HBBHBB` = request_id、opcode、status、target_rpm、direction、run。
status=0 接受，1 参数超界，2 运行中禁止换向，3 停止/时钟保护有效，4 不支持的命令。
确认帧报告更新后的设定与运行命令状态，不证明电机物理转动；需同时看编码器 RPM。
CRC 错误、错误类型/长度或不完整帧不会执行命令。界面不会自动重发未确认的启动命令。
