# 2026-11-04 更新：本地界面控制电机

已增加目标转速输入、应用转速、启动、停止、方向选择和 FPGA 确认反馈。

1. 关闭 D36A 电源，重新下载 `build/rotating_health.bit`。旧比特流没有接收控制命令的逻辑，仅更新 Python 不够。
2. 关闭旧上位机窗口，重新双击 `start_monitor.bat`，选择开发板 USB 串口连接。
3. 收到新版状态后，输入 **10～120 的整数 RPM**，点击“应用转速”。收到“FPGA 已确认”才代表设置被接受。
4. 确认电机轴能安全连续转动后打开 D36A 电源，点击“启动”。运行中也能应用新转速，脉冲频率会渐变。
5. 点击“停止”后，确认界面显示停机，再选择正向/反向并点击“应用方向”。运行中换向会被 FPGA 拒绝。

目标转速是开环 STEP 指令，实测转速仍由编码器显示在 RPM 卡片；未实现 PID 闭环调速。
驱动器需保持 16 细分、1.8° 电机、3200 STEP/rev，设置与实际不符会导致转速比例错误。
改变转速后健康监测基线可能不再适用，应在新工况稳定且正常时按 S1 重新标定。约 12 RPM 以下不满足 FPGA 基线准入的最低转动量；约 94 RPM 以下不输出不平衡/松动的阶次疑似标签，电机控制仍可使用。

通信使用原来的 J6 USB-UART，无需额外飞线。新增 FPGA RX 为 **N5**，TX 仍为 T4，230400 8N1。
通过界面启动后，FPGA 要求控制心跳；约 2 秒没有收到心跳会停机，恢复通信不会自动重启。
界面断开/关闭时尝试发送停止，串口异常时仍可使用板上的 **S4** 或关闭 D36A 电源。
本地 S0 启动仍可脱离电脑工作，不因没有上位机心跳而停止。按住 S4 时上位机不能重新启动电机。

新版 Vivado 工程位于 `build/vivado_control/rotating_health.xpr`。
构建方式和分析功能如下；历史构建路径 `vivado_final` 对应上一版。

# 旋转设备多维状态感知与故障识别

适配现有 EGO1 / Artix-7、ADXL345、MS42CG 编码器和 D36A 驱动器的完整演示工程。
工程按当前 Vivado 配置 `xa7a35tcsg324-1I` 构建，不修改既有诊断工程。

## 首次运行

1. 下载前关闭 D36A 动力电源。核对接线和驱动电流档位，固定电机和传感器。
2. 在 Vivado Hardware Manager 中连接开发板，下载 `build/rotating_health.bit`。
3. 双击 `start_monitor.bat`，选实际 USB 串口并连接，波特率为 **230400**。旧诊断界面和旧比特流与本协议不兼容。
4. 在诊断页确认设备 ID 为 `0xE5`、I²C 错误没有持续增加、手动缓慢转轴时编码器计数变化。
5. 确认旋转范围安全后给 D36A 上电。**S0 现在是连续运行/停止开关，不是此前的 100 脉冲测试。S4 是停止键。**
6. 等待转速稳定；确认设备确实处于正常状态，按 **S1** 学习正常基线。FPGA 接收 8 个合格窗口，最快约 10.24 秒，初始化/转速不稳会延长时间。
7. 波形、频谱、RPM、规则健康指数和疑似故障标签随后更新。重新上电会丢失 FPGA 基线，应重新标定。

无需开发板可双击 `start_demo.bat`。正常情况下先点击“正常基线”，等模拟标定完成，再选择不平衡、松动或转速异常演示。
演示模式使用合成数据，不代表现场故障识别已验证。

## 操作与机械行为

| 按键 | 行为 |
|---|---|
| S0 / R11 | 连续运行 / 停止电机 |
| S1 / R17 | 重新学习正常基线 |
| S2 / R15 | 停机时切换方向，运行时忽略 |
| S3 / V1 | 停机时切换 30、60、120 RPM，默认 60 |
| S4 / U4 | 停止优先，关闭 STEP 和 EN |

上述目标 RPM 假定电机 1.8°、驱动器 **16 细分**，即 3200 STEP/rev。
启动有加速过程，期间“转速异常 / 加速中”是预期提示。方向正负取决于电机和编码器安装。
FPGA 配置后默认关闭使能，不自动旋转。MMCM 失锁后锁存动力输出禁止，重新下载程序才能恢复。
软件不是经过安全认证的机械保护系统；需要硬件切断动力时直接关闭 D36A 电源。

## 已确认的接线

| 设备信号 | EGO1 J5 编号 | FPGA 引脚 |
|---|---:|---|
| ADXL345 SCL | 17 | E15 |
| ADXL345 SDA | 19 | D15 |
| 编码器 A | 25 | H14 |
| 编码器 B | 27 | E17 |
| D36A ST1 | 29 | K13 |
| D36A DIR1 | 31 | H17 |
| D36A EN1 | 30 | J13 |

ADXL345 与编码器用 3.3V 供电；ADXL345 CS 接 3.3V，SDO 接 GND，地址 0x53。
J5 的 33/34 是 GND，35/36 是 3.3V。实物编号方向必须正确，电源和 GND 可通过分线端子共享。
D36A 用独立 12V，控制口 GND 与开发板共地；不要把驱动器的 5V 或电机相线接到 FPGA I/O。
编码器 PWM、Z 当前不使用，不声称提供上电绝对位置。
串口使用 J6 的 USB-UART，FPGA TX 为 T4。程序自动优先选择唯一的 USB 串口，但不会选择蓝牙端口代替。
SCL/SDA 需要适当的外部 3.3V 上拉；XDC 中的弱上拉不能替代总线电气设计。

## FPGA 与上位机的职责

| 功能 | 实现位置 |
|---|---|
| I²C 应答、超时、DEVID 检查与寄存器配置 | FPGA |
| 数据就绪轮询、三轴采集、独立状态心跳 | FPGA |
| 去直流 IIR（α=1/64）和三抽头 FIR（1,2,1）/4 | FPGA，三轴并行 |
| 256 点 Hann 窗、定点 radix-2 FFT | FPGA，X 轴 |
| 三轴平方和、峰值、X 四次方和、过零数 | FPGA |
| 编码器正交四倍频、无效跳变、转速窗口增量 | FPGA |
| 编码器相位同步的 1×、2× 正余弦相关 | FPGA |
| 8 窗口正常基线、能量/速度阈值、健康规则分数 | FPGA |
| RMS 开方、峭度/峰值因数、单位换算和绘图 | Python，使用 FPGA 原始特征 |
| 同工况参考下的不平衡/松动疑似标签 | Python 可解释规则 |
| CSV 记录、特征/频谱 JSONL、波形 CSV 回放 | Python |

真实模式的频谱来自 FPGA，Python 不用 FFT 代替硬件计算。
仅离线合成演示使用 NumPy 生成模拟频谱，界面会明确标识。

## 采样、分辨率和判断边界

- ADXL345 设置为全分辨率 ±2g、200 Hz ODR。I²C 为 100 kHz，轮询 DATA_READY 后连续读六字节，避免简单定时读取造成大量重复样本。
- 当前接口不使用额外 DATA_READY 中断线/FIFO。采样频率使用传感器标称 200 Hz，传感器内部时钟公差和 I²C 轮询抖动尚未做现场计量校准。
- FFT N=256，帧长 1.28 秒，无重叠，频率间隔 0.78125 Hz；采集和 FFT 并行运行。
- 频谱显示 0～100 Hz；受传感器带宽和 FIR 滚降影响，接近 Nyquist 的定量幅值不能当作平坦频响。
- 原始加速度按标称 3.9 mg/LSB 换算，未做传感器灵敏度、安装传递函数或量程饱和的计量校准。若 raw 接近 ±512，先降低机械振动或按数据手册重新设计量程。
- RMS / 峰值等为滤波后的数字振动指标，不是未经滤波的加速度峰值。
- 1×/2× 相关不需要转频正好落在 FFT 栅格；但一个窗口不足两转时，上位机不输出不平衡/松动疑似标签，避免过低速时的误判。
- 编码器默认 **4096 四倍频计数/圈**。厂家资料同时出现 4000 和 4096，必须实际转一圈确认后再用于准确 RPM 和阶次分析。
- 若实测为 4000：执行 `vivado -mode batch -source scripts/build.tcl -tclargs 4000`，并使用该次生成的 `config.json` 和比特流。只改 Python 的除数无法修正 FPGA 阶次相位。
- 未标定、停机、传感器断开、数据过期、编码器异常时不显示“健康正常”。健康指数是能量相对基线的规则评分，不是经过统计校准的故障概率。
- 疑似不平衡、松动/碰摩、转速异常是现场筛查提示，不等于确定故障根因。不同安装、负载、速度需要重新标定与受控故障验证；随机台面晃动不能作为机械故障验证。
- 这版适用于小型低速实验台。高速轴承故障、高频包络分析、声学输入、多传感器融合尚未实现；声学扩展应增加采集接口、同步时基及相应诊断验证。

## 文件与重建

- `rtl/acquisition.v`：I²C、ADXL345、编码器。
- `rtl/dsp.v`：数字滤波、FFT、特征与基线评分。
- `rtl/control_link.v`：按键、电机控制、串口与 CRC 帧。
- `rtl/health_top.v`：顶层、MMCM、并行数据流与状态。
- `constraints/ego1.xdc`：现有接线约束。
- `host/app.py`：本地工作站；`protocol.py`、`analysis.py`：协议与规则。
- `sim/`、`scripts/simulate.ps1`：仿真、数值验证。
- `build/rotating_health.bit`：下载用比特流。
- `build/vivado_control/rotating_health.xpr`：可打开的 Vivado 工程。
- `build/timing.txt`、`utilization.txt`、`drc.txt`：最终实现报告。

在本机使用 Python 3.11.9、NumPy 2.4.6、Matplotlib 3.11.1、pyserial 3.5。
pyserial 附在 `deps` 中；NumPy、Matplotlib、Tk 使用本机已安装环境。
其他电脑可用 `python -m pip install -r requirements.txt`，并调整启动 BAT 中的 Python 路径。

重建：运行 `scripts/build.bat`，使用安装在 D 盘的 Vivado 2025.2。
查表文件可用 `python scripts/generate_tables.py` 重新生成。
内部处理时钟为 MMCM 产生的 50 MHz，保留 EGO1 的 100 MHz 晶振输入。
构建脚本在最终检查 setup 和 hold slack；未通过时不应使用生成的测试位流。

测试：PowerShell 中运行 `scripts/simulate.ps1`，再运行 `python scripts/test_numeric.py`。
仿真覆盖 FFT 数值、基线/振动异常、I²C、UART、编码器与电机停机控制，不替代实物接线验证。

## 记录与排查

“记录 / 停止”保存 CSV（原始和滤波三轴、计数、标志）及同名 `.csv.jsonl`（特征、频谱和标签）。
CSV 回放显示历史波形和计数；它不重建 FPGA 基线，也不把历史数据作为当前设备状态。
需要保留完整频谱和特征时同时保存 JSONL。

如果没有数据，先看诊断页：

1. FPGA 心跳是否闪、下载的是否为本工程位流；旧程序不能与本界面互用。
2. USB 串口是否选对，是否被其他串口助手占用；波特率须为 230400。
3. FPGA 在线但 ID 非 E5 / I²C 错误增加：检查 ADXL345 电源、CS/SDO、SCL/SDA、上拉。
4. 编码器计数不动：先确认轴确实转动，再检查 3.3V、共地与 A/B。手动缓慢转一圈核对 PPR。
5. 电机命令有效但轴不转：检查 D36A MOTOR1、ST1/DIR1/EN1、独立供电、线圈和电流档位。
6. CRC 或缺样增加：检查 USB 线、串口占用与电机电源干扰；不要用丢样记录作准确频谱诊断。
